## Protocol sequence

Use actual POST /sync/history capabilityOnly:true with aggregates:{} and discoveryCursor as needed. Parse all responses against runtime Schema (add exported History/Replay RESPONSE schemas in transfer-protocol.ts while preserving existing types/wire). Discovery/capability page carries no records. Then pull DATA using exactly the original request binding plus SAME sourceSnapshotToken and successive pageCursor. Freeze and compare sourceSnapshotToken/highWater/manifestDigest/discoveryCursor across pages; validate aggregates count<=128, safe sequences, body<=512KiB and no empty nonterminal page. Do not silently switch snapshots or downgrade when a peer rejects v1. A header version, when present, must be1; strict body version1 is required for compatibility with the existing fork endpoints that negotiate through the payload.

For a nonempty highWater start receiver transfer with directory, unique client ID, token/highWater/manifestDigest, expiresAt<=now+30min. Stream each page to /sync/replay append with digest(canonical(page)), correct zero-based pageIndex; validate echoed handle/nextPageIndex. Enforce accumulated wire budget<=512MiB, record/chunk limits and finite progress (cursor cycle rejected). When finished finalize with actual page count/manifestDigest and validate manifestReceipt. On ANY failure/interruption after begin, best-effort authenticated abort of that handle with its own short cleanup deadline, preserving the original error/cause. Completed receipt is never aborted. Continue discoveryCursor batches without losing original page bindings. Empty discovery is a no-op. Full-private snapshot behavior is already source-owned, not reimplemented here. No provider calls or new native tables.

## Source cache lifecycle

Current source retains every snapshot for 5 minutes, including completed ones; a continuous caller can fill eight slots with finished transfers. Add explicit internal completed-state tracking when a terminal DATA page has been produced. Under new-snapshot count/byte pressure, evict oldest completed snapshots before returning busy/too-large; NEVER evict an unfinished snapshot to satisfy new admission. An evicted token gets existing restart error, never rebound data. Continue checking size after awaited exports to preserve concurrency bounds. Capability-only probes that have not been consumed remain unfinished; do not mark them complete. Same-cache retries remain immutable. This is a bounded cache policy, not a new wire endpoint or a promise to retain completed snapshots under pressure. Add tests for repeated completed transfers, active snapshot protection, and cache-pressure restart behavior.
