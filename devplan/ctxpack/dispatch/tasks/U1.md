## 2. Capture rules (implement exactly)

The Block Runtime host wraps each block's rendered content in:

```html
<article data-ctxpack-source-root data-workspace-id="ws-1" data-block-id="block-1" data-functionality-id="builtin:chat">...</article>
```

1. Return `null` for a collapsed selection (`selection.isCollapsed` or empty range).
2. Both Range boundary containers must resolve (via `closest("[data-ctxpack-source-root]")`)
   to the SAME element; else `null` (multi-block selection rejected).
3. Reject if either boundary has an editable ancestor BEFORE the root: walk ancestors
   from the boundary node up to (and excluding) the root; if any is an `input`,
   `textarea`, or `[contenteditable="true"]` (or `isContentEditable` true) → `null`.
4. Text = `selection.toString()` then normalize: `value.replace(/\r\n?/g, "\n").replace(/[ \t]+$/gm, "").trim()`
   (export this as `normalizeSelectedText`). Empty after normalize → `null`.
5. Whitespace-only → `null`. Text over 32 KiB UTF-8 (`new TextEncoder().encode(text).byteLength > 32*1024`) → `null`.
6. Never read `innerHTML`, whole-root `textContent`, clipboard data, or offscreen siblings.
7. `clientFragmentID`: `crypto.randomUUID()`.
8. Source defaults: `kind:"block-text"`, `direction:"unknown"`, `sourceTimestamp:null`,
   `entityRef:null`, `label:null`, `metadata:{}`, `sensitivity:"workspace"`,
   `capturedAt: input.now`; workspace/block/functionality from the dataset attributes.
   Richer descriptors are future work — the plan freezes these defaults for v1.

## 3. Frozen draft controller (`draft.tsx`, SolidJS)

```ts
export interface CtxPackDraftController {
  workspaceID(): string | undefined
  fragments(): readonly CapturedCtxPackFragment[]
  add(fragment: CapturedCtxPackFragment): { status: "added" | "duplicate" }
  remove(clientFragmentID: string): void
  move(clientFragmentID: string, targetOrdinal: number): void
  clear(): void
  byteLength(): number       // sum of UTF-8 bytes over fragments
  estimatedTokens(): number  // Math.ceil(byteLength() / 4)
}
```

Solid context idiom (repo pattern is `createSimpleContext` from `@opencode-ai/ui/context`
— input object form `{ name: string, init: (props) => T }`, returns `{ use, provider }`
LOWERCASE `provider`; if that import gives you trouble in this package, use Solid's
`createContext`/`useContext` with a provider component instead — either is acceptable).
Memory-only provider: no persistence calls anywhere.

Rules:
- `add`: duplicate when an existing fragment has the same normalized text AND the same
  source `{workspaceID, blockID, functionalityID}` → `{ status: "duplicate" }` and no-op.
- Maximum 32 fragments: `add` beyond 32 returns `{ status: "duplicate" }`? NO — freeze:
  beyond 32 the add is accepted at the controller level (the create dialog enforces the
  1–32 budget; controller itself only enforces dedupe and 32 KiB/fragment at capture).
  Keep it simple: controller enforces ONLY dedupe + clear-on-epoch.
- `move(clientFragmentID, targetOrdinal)` reorders (target clamped to [0, len-1]).
- Auto-clear when `workspaceID` or `workspaceEpoch` changes: provider takes
  `props: { workspaceID: Accessor<string | undefined>; workspaceEpoch: Accessor<number> }`
  and `createEffect` on both; any change → `clear()`.
- One shared draft per workspace-shell mount (the host mounts ONE provider; blocks never
  mount their own).

## 4. Frozen keyword suggestions (`keyword-suggest.ts`)

```ts
export function suggestCtxPackKeywords(input: { title: string; fragments: readonly CapturedCtxPackFragment[] }): string[]
```

Deterministic, no network/model:
- Tokenize title and fragment text with Unicode letters/numbers plus `.`, `_`, `-`, `:`
  allowed inside a token (regex: `/[\p{L}\p{N}][\p{L}\p{N}._:\-]*/gu`).
- Drop tokens with < 3 code points UNLESS they contain a digit or `.`/`_`/`-`/`:`.
- Drop a fixed English stop-word set (at minimum: the, and, for, are, but, not, you, all,
  any, can, had, her, was, one, our, out, has, his, its, that, this, with, from, have,
  will, your, they, them, then, than, what, when, where, which, while, who, why, how,
  into, over, under, again, about, above, after, before, between, during, other, some,
  such, only, very, just, more, most, been, being, does, doing, done, each, every, few,
  many, much, must, same, should, could, would, there, their).
- Normalize case for dedupe, preserve the FIRST display form.
- Rank: title tokens first (in first-seen order), then fragment tokens by frequency
  (count across fragments, then first-seen order).
- Return at most 8. Preserve technical tokens like `CtxPack`, `Niagara`, `session.input`,
  `7900XTX` (they survive the rules above).
