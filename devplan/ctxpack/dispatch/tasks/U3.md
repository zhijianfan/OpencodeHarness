## 1. Frozen drag contract (`drag.ts`)

```ts
export const CTXPACK_DRAG_MIME = "application/x-opencode-ctxpack+json"

export interface CtxPackDragPayloadV1 {
  version: 1
  workspaceID: string
  ctxPackID: string
  contentHash: string
  label: string
  estimatedTokens: number
}
export function serializeCtxPackDragPayload(payload: CtxPackDragPayloadV1): string
export function parseCtxPackDragPayload(dataTransfer: DataTransfer): CtxPackDragPayloadV1 | null
```

- Serialize: `JSON.stringify(payload)`. The serialized output MUST NOT contain any
  fragment text field — only the six fields above (test asserts exact key set).
- Parse: read `dataTransfer.getData(CTXPACK_DRAG_MIME)`; empty → `null`. `JSON.parse`
  inside try/catch → `null` on throw. Validate: `version === 1`, non-empty strings for
  workspaceID/ctxPackID/contentHash/label, `typeof estimatedTokens === "number"`,
  AND exact key set `["version","workspaceID","ctxPackID","contentHash","label","estimatedTokens"]`
  (reject extra keys) → else `null`.
- `applyCtxPackDrag(dataTransfer, payload)` helper (used by U2's dragstart): sets the
  custom MIME with the serialized payload, sets `text/plain` to `payload.label` ONLY,
  sets `effectAllowed = "copy"`. Never write content/keywords/source metadata/IDs of
  capsules/authorization data into the DataTransfer.

## 3. Frozen attachment contract (`attachment-store.tsx`)

```ts
export interface ContextAttachmentDraft {
  clientAttachmentID: string
  kind: "context-capsule"
  contextCapsuleID: string
  source: { kind: "ctxpack"; ctxPackID: string; contentHash: string }
  label: string
  contentHash: string
  estimatedTokens: number
  status: "ready" | "error"
  errorCode: string | null
}
export interface SessionContextAttachmentInput {
  contextCapsuleID: string
  label: string
  contentHash: string
  source: { kind: "ctxpack"; ctxPackID: string }
}
export function toSessionContextAttachmentInput(attachment: ContextAttachmentDraft): SessionContextAttachmentInput

export interface ContextAttachmentStore {
  attachments(): readonly ContextAttachmentDraft[]
  addCtxPack(payload: CtxPackDragPayloadV1, target: { instanceID: string; functionalityID: string }): Promise<void>
  remove(clientAttachmentID: string): void
  clearAfterAdmission(): void
  restoreAfterFailure(snapshot: readonly ContextAttachmentDraft[]): void
  totalEstimatedTokens(): number
  pendingCount(): number
}
export const ContextAttachmentStoreContext = /* Solid context */
export function useContextAttachmentStore(): ContextAttachmentStore
export const MAX_CONTEXT_ATTACHMENTS = 8
export const MAX_CONTEXT_ATTACHMENT_TOKENS = 6_000
```

Provider: Solid context provider component whose props are
`{ workspaceID: Accessor<string | undefined>; materialize: (input: {
  workspaceID: string; ctxPackID: string; expectedContentHash: string;
  targetInstanceID: string; targetFunctionalityID: string
}) => Promise<{
  contextCapsuleID: string; sourceCtxPackID: string; label: string;
  contentHash: string; estimatedTokens: number
}> }` — the injected typed facade of `ctxpack.materialize` (M1 wires the real SDK).

`addCtxPack` semantics (frozen):
1. workspace undefined or `payload.workspaceID !== workspaceID()` → reject
   `new Error("cross-workspace")` BEFORE any materialize call (no network).
2. duplicate: existing attachment with same `source.ctxPackID + contentHash` → no-op
   (resolve silently, no second materialize call).
3. count: ≥ 8 ready/pending attachments → reject `"attachment-limit"` (stable error code
   strings: `"cross-workspace"`, `"attachment-limit"`, `"token-limit"`,
   `"materialize-failed"`, `"offline"`).
4. `totalEstimatedTokens() + payload.estimatedTokens > 6000` → reject `"token-limit"`.
5. create a PENDING item internally (clientAttachmentID via `crypto.randomUUID()`,
   status "error" with `errorCode:"pending"`? NO — freeze: pending items are INTERNAL
   and not exposed in `attachments()`; only `pendingCount()` reflects them. `attachments()`
   exposes only ready/error items), call `materialize(...)` with
   `targetInstanceID`/`targetFunctionalityID` from the drop target. On success: add a
   ready `ContextAttachmentDraft` (contextCapsuleID/label/contentHash/estimatedTokens
   from the result). On failure: NO ready item, NO fake chip; error surfaces via the
   rejecting promise with the stable code (callers/toasts show it). Pending count
   decrements in both cases.
6. `remove` deletes by clientAttachmentID. `clearAfterAdmission` drops all.
   `restoreAfterFailure(snapshot)` replaces the store contents (optimistic rollback
   support for U5).
7. Never store fragment text; attachments carry capsule ID + hashes + label only.
