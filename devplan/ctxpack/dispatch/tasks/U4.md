## 2. Overlay behavior

- Listen for `selectionchange` + `pointerup` + `keyup` (shift+arrow selection completion)
  with scoped document listeners disposed on `onCleanup`; throttle repositioning with ONE
  `requestAnimationFrame` per change; never poll.
- On each selection event: `captureCtxPackSelection({ selection: window.getSelection(),
  now: Date.now() })`; non-null → show a compact floating toolbar positioned near
  `range.getBoundingClientRect()` (clamped to viewport); null/collapsed → hide.
- Hide when: selection collapses; `workspaceID()` or `workspaceEpoch()` changes
  (createEffect); Escape pressed; user starts editing (editable target in the event).
- Actions:
  - **Add to CtxPack draft**: call the U1 draft controller `add(fragment)`; duplicate →
    show "Already in draft" (non-blocking toast/text); then `window.getSelection()
    ?.removeAllRanges()`.
  - **Save as new CtxPack**: `add(fragment)` then open the create dialog (pass a
    signal/toggle to `CtxPackCreateDialog`).
- Clicking INSIDE the overlay must NOT collapse the captured Range before the action runs
  (mousedown on the toolbar → `preventDefault()` so the selection survives).
- The selected text NEVER appears in `data-*` attributes, URLs, toasts, or console output.

The overlay + dialog need the U1 draft controller: accept it via Solid context
(`useCtxPackDraft()` — import from U1's `draft.tsx`) so the host mounts ONE provider
(M1 wires). If U1's context hook name differs, import what its HANDOFF documents and note
it in your HANDOFF.

## 3. Create dialog behavior (`create-dialog.tsx`)

```ts
export interface CtxPackCreateDialogProps {
  open: Accessor<boolean>
  onClose(): void
  workspaceID: Accessor<string | undefined>
  create(request: CtxPackCreateRequestLocal): Promise<CtxPackInfoLocal>
  onCreated?(pack: CtxPackInfoLocal): void
}
```

- Title input: defaults to the first non-empty line of the first fragment's text
  (truncated to 80 display chars) but editable up to 120 code points.
- Keywords: prefilled from `suggestCtxPackKeywords({ title, fragments })`, editable
  (comma/space-separated chips input; max 12).
- Fragment list: every draft fragment, remove (✕) and reorder (up/down) controls; shows
  source block/functionality + capture time; per-fragment byte/token counts; aggregate
  `byteLength`/`estimatedTokens` footer.
- Sensitivity: radio of public/workspace/private. Compute the floor:
  `rank = { public: 0, workspace: 1, private: 2 }`; `minimum = max over fragments of
  rank[fragment.source.sensitivity]`. DISABLE weaker choices (never silently upgrade);
  select the minimum by default.
- Save disabled when: empty draft, empty/invalid title, > 32 fragments (controller caps
  at 32 — still guard), aggregate > 32 KiB or > 6,000 tokens, weaker sensitivity than
  floor selected, or a request is in flight.
- Save: build `CtxPackCreateRequestLocal` with fragment order preserved,
  `idempotencyKey = crypto.randomUUID()` ONCE PER SAVE ATTEMPT (regenerated after a
  failure so retry isn't deduped by the server); double-click while pending → exactly ONE
  request. On success: clear the draft, close the dialog, call `onCreated(pack)`. On
  failure: PRESERVE the draft and fields, show a stable error message WITHOUT fragment
  text (use the facade's errorCode when present).
- Closing without save preserves the draft. Explicit **Discard draft** button clears it
  after a confirm step (simple inline confirm state, no window.confirm).
- No direct list-state writes: the browser updates via EventV2/refetch (M1/R1). Never
  write to localStorage/layout.
