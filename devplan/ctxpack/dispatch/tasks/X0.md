## 4. Frozen policy (explicit, deny-first, host-authoritative)

Evaluate in order; first matching rule decides:

1. **Not a member**: `WorkspaceMembership.isMember(userID, subject.workspaceID) === false`
   → deny, reason `"not-workspace-member"`.
2. **Unknown operation** → deny, reason `"unknown-operation"`.
3. **CtxPack sensitivity "private"**: if `userID !== subject.createdByUserID` → deny for
   EVERY operation, reason `"private-pack-not-owned"`.
4. **Required rights**: every right in `requiredRights[operation]` must be granted to the
   user. Grant source: for v1 the workspace membership confers all three rights
   (`read`/`write`/`execute`) to every member. THE POLICY HOOK for finer roles is a pure
   injected provider `UserWorkspaceRights: (userID, workspaceID) => Effect<Right[]>` —
   default implementation returns `["read","write","execute"]`; M1 swaps in the real
   role/attribute provider later. Your tests inject custom providers to build read-only
   and write-only users. Deny reason `"insufficient-rights:<right>"` when missing.
5. **Explicit deny list wins** (built-in): subject `{ type: "FunctionalityInstance",
   functionalityID: "builtin:chat" }` with operation `chat.context.attach` → allowed only
   when rule 4 passes (no extra deny in v1). Keep the deny list as a frozen empty-by-
   default structure `denyRules: Array<{ operation: string; subjectType: string }> = []`
   that future code can extend; document it.

`require` maps a deny to an error: `{ _tag: "CtxPackPermissionDenied"; operation: string }`
— this exact `_tag` is the frozen error shape used by lanes C1/X1/P1/Q1 (define the
TaggedError in `service.ts`; the full CtxPackError union lives in S1's schema file — do
NOT import it; a structurally identical local error is fine and M1 aligns the import).

No secret material in subjects, results, or errors. Never log content.

## 5. Context capsule store (`context-broker/capsule.ts`)

Capsule type — schema exists at `@opencode-ai/schema/functionality` as `Functionality.Capsule`:

```ts
// packages/schema/src/functionality.ts (already exists — import from there, do NOT edit it):
export const Capsule = Schema.Struct({
  id: Schema.String, version: Schema.Literal(1), workspaceId: Schema.String,
  purpose: Schema.String, audience: Schema.Array(Schema.String),
  summary: optional(Schema.String), facts: Schema.Array(Schema.Unknown),
  references: Schema.Array(Schema.Unknown), artifactRefs: Schema.Array(Schema.Unknown),
  recentEvents: Schema.Array(Schema.Unknown), contentHash: Schema.String,
  createdAt: NonNegativeInt, expiresAt: optional(NonNegativeInt),
}).annotate({ identifier: "Functionality.Capsule" })
```

Note: the spec's `ContextCapsule` also carries `createdBy {userId, instanceId}` and
`budget`; the schema type has no room for them. Freeze this: `createdBy` and `budget`
are stored OUT-OF-SCHEMA in the durable row as separate JSON columns (created_by_json,
budget_json), while the schema-typed capsule JSON is stored in `capsule_json`. Frozen
extended capsule type (exported from capsule.ts):

```ts
export interface StoredCapsule extends Functionality.Capsule {
  createdBy: { userId: string; instanceId: string; operationId?: string }
  budget: ContextBudget
}
export interface ContextBudget {
  maximumBytes: number; maximumEstimatedTokens: number; maximumFacts: number
  maximumReferences: number; maximumArtifacts: number; maximumRecentEvents: number
}
export const DefaultInteractiveContextBudget: ContextBudget = {
  maximumBytes: 32 * 1024, maximumEstimatedTokens: 6_000, maximumFacts: 32,
  maximumReferences: 16, maximumArtifacts: 8, maximumRecentEvents: 8,
}
```

Frozen store interface (X1 and Q1 consume EXACTLY this):

```ts
export interface ContextCapsuleStore {
  store(capsule: StoredCapsule): Effect.Effect<StoredCapsule>            // assigns id if empty (ctxkpsl_ + ascending pattern); workspace-scoped; immutable after write
  get(workspaceID: string, capsuleID: string): Effect.Effect<StoredCapsule | undefined>
  materialize(input: {
    workspaceID: string
    capsuleID: string
    requestedRefs: string[]            // empty = all references
    budget: ContextBudget
  }): Effect.Effect<
    | { status: "ok"; capsule: StoredCapsule; content: { facts: unknown[]; references: unknown[]; artifactRefs: unknown[] }; unresolvedRefs: string[]; byteLength: number; estimatedTokens: number }
    | { status: "not-found" } | { status: "expired"; expiresAt: number } | { status: "over-budget"; limit: "bytes" | "tokens"; current: number; maximum: number }
  >
}
export class Service extends Context.Service<Service, ContextCapsuleStore>()("@opencode/v2/ContextCapsuleStore") {}
```

Durable table (raw SQL migration — drizzle idiom per session/sql.ts; migration file
`20260821_capsule`, id `20260821_capsule`):

```sql
CREATE TABLE context_capsule (
  id TEXT PRIMARY KEY,
  workspace_id TEXT NOT NULL,
  purpose TEXT NOT NULL,
  content_hash TEXT NOT NULL,
  capsule_json TEXT NOT NULL,          -- schema-validated Functionality.Capsule JSON
  created_by_json TEXT NOT NULL,
  budget_json TEXT NOT NULL,
  created_at INTEGER NOT NULL,
  expires_at INTEGER NULL
);
CREATE INDEX context_capsule_workspace ON context_capsule(workspace_id, created_at DESC);
```

`store`: encode `capsule_json` with `Schema.encodeSync(Functionality.Capsule)` (strip
createdBy/budget first), decode on `get` and re-attach createdBy/budget; if stored JSON is
corrupt → a typed error (TaggedError `"ContextCapsule.Corrupt"`), never silent skip.
`materialize`: budget-check = bytes (JSON.stringify byte length of the materialized
content) and `Math.ceil(bytes/4)` tokens against the passed budget; refs filter by
`requestedRefs` matching `ref.id` when present (references are unknown-typed at schema
level; at runtime for CtxPack they carry `{ ref: { type: "ctxpack-fragment", id } }` —
match on `ref?.id`); expiry check; NO rights checks here (X1 performs capability checks —
this store is mechanical). Redaction: errors/logs carry IDs, hashes, counts, sizes ONLY —
never facts/references/summary content.

Drizzle module: define the table with `sqliteTable("context_capsule", {...})` in
`capsule.ts` (fields above; capsule_json/created_by_json/budget_json as `text({mode:"json"})`)
AND create it in the migration with the same raw SQL (migration is the source of truth for
the DB; the drizzle table drives queries). Both must agree exactly.
