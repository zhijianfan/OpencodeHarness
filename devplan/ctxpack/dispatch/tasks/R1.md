## 4. resolve (mount)

1. `await services.workspace.awaitDescriptorPersisted(block.id, signal)`.
2. Issue ONE initial `ctxpack.list` with the default query
   (`{ query:"", ...filters null, includeDeleted:false, sort:"created-desc", cursor:null,
   limit:30, workspaceID: workspaceID }`).
3. Errors: a 403/permission-denied shaped error → resolved state carries
   `status: "permission-denied"` (put `status` + `errorCode` ON the resolved object:
   extend CtxPackBrowserResolved with `status: "loading"|"ready"|"permission-denied"|"unavailable"|"error"` and `errorCode: string | null`); unavailable host → `"unavailable"`; never fake an empty list as success.
4. All fetches honor `signal`; on abort, stop mutating state (old workspace responses can
   never overwrite new state: every mutation checks `requestGeneration` + `workspaceID`).

## 5. Events (EventV2 only — no polling, no second stream)

```ts
eventKeys: (resolved) => [{ type: "workspace.ctxpack.changed", workspaceID: resolved.workspaceID }]
onEvent: ({ event, resolved }) => { /* matching event → "invalidate"; anything else → "ignore" */ }
```

- `onEvent` returns `"invalidate"` ONLY for matching `workspace.ctxpack.changed` events
  in the same workspace (never a projection patch from the payload).
- Burst events coalesce into ONE authoritative refetch (trailing debounce ~150 ms —
  setTimeout + clearTimeout on dispose).
- `services.eventRouter.onReconnect(...)` → force authoritative refetch.
- Transient refetch failure: keep last valid items, set status `"stale"`; next successful
  refetch restores `"ready"`.
- No setInterval/EventSource/WebSocket.

## 6. dispatch (commands)

- `set-query`: increment `requestGeneration`, abort the prior in-flight request (track
  AbortController per request), reset cursor, replace the list. Merge the patch into the
  query; changing any field except cursor forces `cursor = null`. Persist the query to
  `services.localView` under key `opencode.canvas.local-view.v1:ctxpack-browser:<blockID>`
  (localView is per-block keyed — write the whole local view object `{ query }`; read it
  back in resolve to restore query; NEVER store items/selected/contents in local view).
- `load-more`: fetch with the current cursor, append unique IDs, adopt next cursor.
- `open`: `ctxpack.get(ctxPackID)`; store `selected`. Opening an already-selected pack
  with unchanged revision reuses current detail. If get says deleted/missing →
  close detail + authoritative list refetch.
- `patch-metadata` / `remove` / `restore`: call the typed endpoints, then ONE
  authoritative list refetch (and detail refetch when selected). No client-side synthesis
  of durable state.
- Late responses with an old generation are dropped. Errors → `errorCode` on resolved
  state; keep prior items.

## 7. select + dispose

`select`: map `CtxPackBrowserResolved` → U2's `CtxPackBrowserView` exactly (status,
query, items, nextCursor, selected, loadingMore: false, errorCode, capability flags
canCreate/canPatch/canDelete/canMaterialize: true for v1 — note in HANDOFF that real
capability projection arrives post-M1). `dispose`: abort in-flight requests, clear
coalesce timer, unsubscribe event listeners (router `on` returns unsubscribe fns);
never deletes packs or cancels host work.
