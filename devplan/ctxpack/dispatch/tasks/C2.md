## 1. Event publisher (`events.ts`) — publisher-port idiom (inlined from
`workspace/functionality-instance-events.ts`)

```ts
export const CtxPackChanged = /* S1's definition, re-export from @opencode-ai/schema/ctxpack */
export type CtxPackChangedEvent = { type: "workspace.ctxpack.changed"; properties: { workspaceID: string; ctxPackID: string; revision: number; change: "created" | "metadata-updated" | "deleted" | "restored" | "used" } }
export interface CtxPackEventPublisher { publish(event: CtxPackChangedEvent): Effect.Effect<void> }
export class CtxPackEventPublisherService extends Context.Service<CtxPackEventPublisherService, CtxPackEventPublisher>()("@opencode/v2/CtxPackEventPublisher") {}
export const make = (events: Pick<EventV2.Interface, "publish">): CtxPackEventPublisher => ...  // decode-validate + events.publish(S1.CtxPackChanged, data), map decode failure to a typed InvalidCtxPackChangedEventError then Effect.orDie
export const layer = Layer.effect(CtxPackEventPublisherService, Effect.gen(function* () { const events = yield* EventV2.Service; return make(events) }))
export const node = makeGlobalNode({ service: CtxPackEventPublisherService, layer, deps: [EventV2.node] })
```

- The event is a TRANSIENT hint (like functionality-instance events): live subscribers
  only, authoritative state is the database. EventV2 is the ONLY transport — no custom
  stream, cursor, or polling loop.
- Event payload JSON keys are EXACTLY `type` + `properties.{workspaceID, ctxPackID,
  revision, change}`. No title/keyword/fragment/label/source/capsule/content keys, ever.

Durable ledger (migration `20260821_ctxpack_usage`):

```sql
CREATE TABLE ctx_pack_usage_admission (
  ctx_pack_id TEXT NOT NULL,
  session_input_id TEXT NOT NULL,
  time_recorded INTEGER NOT NULL,
  PRIMARY KEY(ctx_pack_id, session_input_id)
);
```

Transaction per call (one tx for all packs in the input):
1. for each DISTINCT ctxPackID: `INSERT ... ON CONFLICT DO NOTHING`;
2. ONLY when inserted: `repo.recordUse(workspaceID, ctxPackID, admittedAt)` (S1's
   method increments attached_count + max last_attached_at);
3. after commit: publish ONE `{ change: "used" }` event per newly counted pack.
Idempotent: same sessionInputID twice → counts increment once, second call is a no-op
(after-commit events NOT re-emitted).
