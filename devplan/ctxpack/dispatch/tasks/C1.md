## 2. Validation (`validation.ts`) — exact limits

```text
Title: 1–120 Unicode code points after trim.
Keywords: 0–12; each 1–48 code points after normalizeKeyword; case-insensitive dedupe (normalized form).
Fragments: 1–32.
Each fragment: non-empty after normalizeSelectedText; max 8 KiB UTF-8.
All fragments combined: max 32 KiB UTF-8 and 6,000 estimated tokens (estimateTokens(bytes)).
Source workspace: exactly request.workspaceID (else CtxPackCrossWorkspaceDenied).
Source sensitivity: public|workspace|private; "secret" can never decode (schema-level) — service re-checks.
Requested pack sensitivity: must be >= strictest source (rank public:0 < workspace:1 < private:2);
  weaker → reject CtxPackInvalidSelection (never silently upgrade).
List limit: 1–50 (clamp or reject — freeze: reject with CtxPackInvalidSelection).
Query length: 0–256 code points (reject above).
```

Errors use the frozen `CtxPackError` union tags from S1's schema types (`CtxPackInvalidSelection`,
`CtxPackBudgetExceeded`, `CtxPackCrossWorkspaceDenied`, `CtxPackSecretSourceDenied`).

## 3. Service behavior (`service.ts`)

- **create**: `actor.workspaceID === request.workspaceID` (else PermissionDenied).
  Capability check via `CapabilityService.require({ userID: actor.userID, operation:
  "ctxpack.create", subject: { type: "Workspace", workspaceID: actor.workspaceID } })`.
  Validate (validation.ts). Normalize each fragment text + keywords. Server-assign
  ordinals in REQUEST ORDER (client order preserved, not re-sorted). Compute
  contentHash/byteLength/estimatedTokens. `createdByUserID = actor.userID` (never
  trusted from client input — request has none). Call `repo.create`; on success publish
  `{ change: "created" }` through the event port AFTER commit; event-publish failure is
  swallowed-logged (record through the port's own error path) and must NOT roll back the
  commit. Idempotent replay (same key) → no second `created` event.
- **get**: capability check `"ctxpack.read"` with subject `{ type: "CtxPack", ... }`
  (needs pack sensitivity/owner — fetch the pack first via repo.get with
  includeDeleted=true, THEN check, then re-check deleted state; deleted + includeDeleted
  false → `CtxPackDeleted`).
- **list**: capability check `"ctxpack.read"` with Workspace subject (pack-level
  filtering of private packs happens in the repository query? NO — freeze: the service
  passes a `viewerUserID` filter: private packs of OTHER users are excluded from list
  results at the repository predicate level. Add `viewerUserID` to the list input you
  forward (extension field, documented in HANDOFF — S1's repo accepts it or you add the
  filter post-query; simplest correct: filter post-query in the service).
- **patch/remove/restore**: capability `"ctxpack.patch"/"ctxpack.remove"/"ctxpack.restore"`
  with CtxPack subject; patch validates title/keywords/sensitivity (same limits; weaker
  sensitivity than any fragment source → reject); repo enforces expectedRevision.
- All mutations publish the matching change event (`metadata-updated` | `deleted` |
  `restored`) after commit, payload ONLY `{workspaceID, ctxPackID, revision, change}`.

## 5. Search (`search.ts`) + FTS

- `buildFtsQuery(query: string): string | null` — tokenize on whitespace; normalize each
  token; wrap each token in double quotes (phrase per token); join with `" "` (AND);
  escape embedded double quotes by doubling them; empty/whitespace query → `null` (skip
  MATCH). NEVER interpolate raw query text unquoted. Example: `session.input` →
  `"session.input"`.
- `matchFts(db, workspaceID, query)` and `searchPacks(...)` executing the repository list
  with the FTS filter: `WHERE workspace_id = ? AND ctx_pack_fts MATCH ?` joined via
  `ctx_pack_id` (parameterized, no string concat into SQL). Metadata filters
  (sourceBlockID/sourceFunctionalityID/sourceKind/keyword/sensitivity/created range)
  INTERSECT with FTS (AND), never replace it.
- Keyword filter matches `ctx_pack_keyword.keyword_normalized = normalizeKeyword(input)`.
- Date range: createdAfter/createdBefore on `time_created` (inclusive bounds).
- Sort + cursor: keyset pagination `(sortValue, id)` with the S1 cursor codec; all seven
  sorts; tie-breaker always `id`. Punctuation-heavy query must not throw.
