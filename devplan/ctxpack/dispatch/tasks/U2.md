## 2. Frozen view/command contract (`view-model.ts`)

```ts
export interface CtxPackBrowserView {
  status: "loading" | "ready" | "stale" | "permission-denied" | "unavailable" | "error"
  query: CtxPackListQuery
  items: CtxPackSummary[]
  nextCursor: string | null
  selected: CtxPackInfo | null
  loadingMore: boolean
  errorCode: string | null
  canCreate: boolean
  canPatch: boolean
  canDelete: boolean
  canMaterialize: boolean
}
export type CtxPackBrowserCommand =
  | { type: "set-query"; patch: Partial<CtxPackListQuery> }
  | { type: "load-more" }
  | { type: "open"; ctxPackID: string }
  | { type: "close-detail" }
  | { type: "patch-metadata"; ctxPackID: string; expectedRevision: number; patch: CtxPackPatchInput }
  | { type: "remove"; ctxPackID: string; expectedRevision: number }
  | { type: "restore"; ctxPackID: string; expectedRevision: number }

export interface CtxPackBrowserProps {
  view: Accessor<CtxPackBrowserView>
  dispatch(command: CtxPackBrowserCommand): Promise<void>
  createDragPayload(summary: CtxPackSummary): string
  attachToFocusedInput(summary: CtxPackSummary): Promise<void>
}
```

## 3. Component behavior (SolidJS, strict content safety)

`index.tsx` renders `CtxPackBrowser` (default export component taking
`CtxPackBrowserProps`):
- status `"loading"` → skeleton only; NO stale list controls.
- `"permission-denied"` → explicit message + errorCode; `"unavailable"` → explicit
  message (no fake empty list). `"error"` → error state + errorCode.
- `"stale"` → render last items WITH a visible stale badge (aria-label "stale data").
- `"ready"` → search input, filter controls, sort selector, cards, load-more button.
- empty query with no items vs query with no results → DISTINCT copy.
- deleted items render ONLY when `query.includeDeleted === true` (show a "deleted" badge).
- `loadingMore` → spinner on the load-more button; load-more appends (caller replaces
  list via adapter — you just dispatch `{type:"load-more"}`).
- detail view: `open`/`close-detail` handled via dispatch; when `view.selected` is set,
  render `CtxPackDetail` — every fragment in ordinal order with source
  workspace/block/functionality/timestamp metadata; fragment text rendered as TEXT
  (selectable `<pre>`-like, `user-select: text`), NEVER `innerHTML` / `unsafeHTML` /
  `textContent` injection of markup.
- **Drag icon**: the detail header shows a package icon with `draggable={true}`,
  accessible label "Drag pack to attach", `onDragStart` calls
  `event.dataTransfer.setData(CTXPACK_DRAG_MIME, props.createDragPayload(summary))` and
  `setData("text/plain", summary.title)` with `effectAllowed="copy"`. The MIME constant
  string is frozen (matches lane U3): `"application/x-opencode-ctxpack+json"` — declare
  it locally in `types.ts` as `export const CTXPACK_DRAG_MIME = ...`.
- **Keyboard attach**: detail header button "Attach to focused input" calls
  `props.attachToFocusedInput(summary)`; detail also offers `onPreview` per fragment? NO —
  v1: detail displays all fragments directly (they were authorized by get). Keep scope.

`filters.tsx` — metadata filter controls (source kind, sensitivity, keyword, created
before/after, includeDeleted toggle): each change dispatches
`{ type:"set-query", patch: { ...field, cursor: null } }` — the caller (adapter) replaces
the list; you NEVER mutate `view.query` directly. Textual search debounces 200 ms before
dispatching (clear the timeout in `onCleanup`).

`ctxpack-card.tsx` — per card: title, keyword chips (max 4 + "+N"), fragment count,
source block/functionality summary (e.g. "2 blocks · builtin:chat"), created timestamp
(short form), estimated tokens, attached count / last attached. Click card →
dispatch `{type:"open", ctxPackID}`. Patch/delete/restore buttons only when
`view.canPatch` / `view.canDelete`; each enters a LOCAL pending visual state (local
signal), calls dispatch, then relies on the refreshed projection (no direct store
mutation). `aria-live="polite"` region announces materialization/attach failures via
status text passed in `errorCode`.
